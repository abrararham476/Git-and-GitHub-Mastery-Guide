Introduction: Git vs. GitHub

Understanding the fundamental distinction between the local tool and the cloud platform.

Git

Distributed Version Control System (DVCS)
Local CLI Tool

Git is an open-source command-line tool installed on your local system. It tracks code changes, manages branches, creates snapshot commits, and allows fully offline software development.

  • Works entirely offline on your machine
  • Stores full history inside hidden .git/ directory
  • High speed branching & merge handling

GitHub

Cloud Hosting & Collaboration Platform
Web Service

GitHub is a cloud service built around Git. It hosts remote repositories online and adds critical team tools: Pull Requests, code reviews, automated CI/CD pipelines, issue tracking, and security scanning.

  • Requires internet connectivity to synchronize
  • Adds Pull Requests, Issues, Actions & Codespaces
  • Cloud backups, access control & team permissions

GitHub Features & PR Workflow Explorer

How engineering teams collaborate, review code, and maintain software safety on GitHub.

The Standard Pull Request (PR) Workflow Lifecycle

1

1. Fork or Branch

Create a isolated feature branch locally (git checkout -b feat/auth).

2

2. Commit & Push

Make changes, commit with clear messages, and push your branch to GitHub.

3

3. Open Pull Request

Submit a PR describing changes, linking issues, and requesting reviews.

4

4. Code Review & CI

GitHub Actions run automated tests while teammates leave inline feedback.

5

5. Merge to Main

Once approved, squash or merge PR into the production branch.

Forks vs. Clones

A Fork creates a server-side personal copy of someone else's repository under your account on GitHub. A Clone downloads a repository to your local computer.

GitHub Actions (CI/CD)

Automate software workflows using YAML files in .github/workflows/. Run tests, perform linting checks, or deploy code on every push or Pull Request automatically.

Branch Protection Rules

Enforce safeguards on primary branches (e.g., main): require 1-2 approving reviews, mandate passing CI builds, and block force pushes.

Workflows & Commit Best Practices

Industry standard branching strategies and conventional commit standards.

Structured Enterprise Model

Git Flow Strategy

Uses long-lived branches (main, develop, release, hotfix) along with short-lived feature branches. Best suited for scheduled software releases.

  • Strong control over scheduled releases
  • Clear separation between production & active development
Modern Continuous Delivery

Trunk-Based Development

Developers merge small, frequent updates directly into a single central branch (main or trunk). Supported by feature flags and automated CI testing.

  • Minimizes long-lived merge conflicts
  • Rapid deployments & continuous integration

Conventional Commit Standards

Standardize your commit messages to generate automatic changelogs and maintain clean commit histories:

feat: ... Adds a new feature to the application
fix: ... Fixes a bug or error in codebase
docs: ... Documentation edits or additions
refactor: ... Code rewrite without changing behavior
